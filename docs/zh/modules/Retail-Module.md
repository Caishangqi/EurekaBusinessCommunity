# Retail 零售模块与扩展点

Retail 模块基于 Core 契约实现核心零售经营玩法。

## 功能边界

Retail 负责：

- 店铺边界、入口、出口与营业开关状态；
- 陈列基座、商品陈列库存和价格牌模块；
- 商品价值目录与四档价格心理反应；
- 顾客生成、购物规划、商品选购、购物篮与收银结算；
- 零售交易记录与世界状态持久化恢复。

## 商品目录结构

`CatalogItemDefinition` 包含物品 ID、四档价格区间 `PriceBand` 以及关联的 `List<CatalogElement>`。每个 `CatalogElement` 引用要素的完整注册键与 `1..9` 的等级数值。目录配置由服务端加载并发布为只读快照。

## 公开价格与成交原则

顾客根据基座价格牌的公开标价进行决策。同款商品优先走向低价基座，但最终拉杆结算时必须在服务端严格校验基座数据版本、库存余量、标价以及完整的物品数据组件。任一步骤失败均不会产生部分结算。

## 附属开发建议

附属模组应通过 Core 提供的要素与变体公共契约进行内容扩充。避免让 Retail 反向依赖附属模组，也不得直接修改 Retail 的内部快照。需要新增零售能力时，应在公开契约层或独立适配层中进行扩展。

## 当前能力边界

商品目录目前为配置驱动的服务端能力，未在公开 API 或当前配置契约中声明的属性不得作为整合包扩展点。
