# 整合包配置与调试

本文档面向整合包作者与测试人员。

## 推荐的整合流程

1. 使用目标 Minecraft `1.21.1` 与 NeoForge `21.1.x` 建立测试实例；
2. 安装 EurekaBusiness 及其声明的外部依赖；
3. 首次启动生成配置后，停止实例再编辑商品目录；
4. 在专用服务器上测试商品识别、价格同步、顾客购买和世界重启恢复；
5. 将验证后的配置纳入整合包发行流程，并保留版本变更说明。

## 开发期重置

根项目提供 `resetRetailConfig` Gradle 任务，用于清理 `runs/` 目录下的开发配置，使目录在下一次启动时重新从代码种子生成：

```text
gradlew resetRetailConfig
```

该命令面向 EurekaBusiness 开发环境。整合包发布者不应让玩家依赖此 Gradle 任务，亦不可在普通启动路径中自动清空用户配置。

## 服务端验证清单

- 目录更新后客户端看到的元素和价格与服务端快照一致；
- 未注册物品或元素不会发布为有效目录；
- 同款不同价时顾客优先前往低价基座；
- 交易失败不会导致库存扣减或收益异常；
- 保存、重启和重连后目录、顾客状态与交易记录保持一致；
- 关闭店铺时不再生成新顾客，已有顾客按关店流程正常完成结算并离店。

## 架构边界提醒

- 不要把 `Documentation/` 或本 Wiki 当作运行时配置文件；
- 不要把 `.reference/` 内容作为发行资源或运行时依赖；
- 客户端传入的价格、物品或元素列表不可直接信任；
- 禁止通过逐 tick 扫描全店实现整合逻辑，应监听配置更新、库存变化或服务端事件。
